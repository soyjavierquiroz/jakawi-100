# MEDIA PIPELINE V1

Status: **MEDIA PIPELINE V1 LIVE** · **MEDIA GC LIVE**. Application release: `dbbaadcd0ab4ee8accb2a5367d2d3104ba80f878`.

Canonical normal-image workflow: device upload → authoritative validation → normalization → temporary private MinIO object → verified immutable object → committed DB reference → optimized delivery → GC lifecycle.

`ImageUpload` is the shared editor selector. It supports drag/drop, device selection, immediate local preview, upload progress, processing, errors, change and removal. `/media/uploads` uses session authentication, CSRF and throttling. Its encrypted upload receipt binds the temporary object to its uploader and expires after 24 hours. Browsers receive no storage credentials or object-key editor. Final forms retain their existing authorization. Direct multipart uploads remain supported by the same backend for existing clients, including the profile crop adapter.

`MediaUploadService` extends the existing storage abstraction. Existing model path columns remain authoritative; no MediaAsset table or migrations are needed. `MediaReferences::FIELDS` explicitly lists Partner logo/cover, Location image, Benefit image, Experience image/cover, Challenge hero, Unlock hero, LandingPresentation hero and UserProfile avatar. Add every future authoritative media field to this list before shipping it.

Accepted content: decoded JPEG, PNG, WebP, maximum 10 MiB, 24 megapixels and 16000 pixels per side. MIME comes from file content; arbitrary SVG and failed decoding are rejected. PHP 8.4 Docker includes GD JPEG/PNG/WebP and EXIF support. Photos are oriented from EXIF (including mirrored orientations), resampled without upscaling and encoded as WebP quality 82 with aspect ratio preserved and longest side at most 1600. Re-encoding discards EXIF/location/unnecessary metadata. Raw camera originals are not retained indefinitely: they remain only in PHP's request temporary file, which is discarded after the request.

Keys: `{kind}/{numeric-id}/{slot}/{server-uuid}.webp`. They are immutable, unique and independent of title/slug/client filename. Kinds include partners, locations, benefits, experiences, challenges, unlocks, landings and avatars. Legacy recognized immutable raster keys continue to work. Temporary keys are `tmp/{server-uuid}/master.webp`; only normalized masters are staged.

MinIO remains private. `MediaUrl` signs existing imgproxy URLs. Runtime imgproxy remains responsible for responsive transformations; no redundant stored variant family is generated. The normalized master bounds source costs. Hero candidates include 480, 960 and 1600 (plus existing 320/640 candidates); small presets cap widths for thumbnails/cards. imgproxy's resize does not enlarge small sources. `JakawiImage` and landing/native adapters receive server-signed srcsets with sizes. No original camera image is exposed. Existing VSL YouTube, MP4 and Bunny HLS architecture is unchanged.

Safe replacement: normalize/stage new → write final object → verify existence and size → persist reference within the form's DB transaction → commit. A failure leaves the saved old image/reference intact; unattached newly written objects are collected later. Removing an image clears only the DB reference. Physical deletion is exclusively GC. Shared references, drafts and archived records protect objects equally.

GC: `php artisan media:gc --dry-run` reports without writing/deleting anything. `php artisan media:gc` reports scanned, referenced, recent orphans skipped, temporary expired, candidates, candidate markers recorded, deleted, bytes reclaimed and errors. Use these commands only inside project Docker; isolated testing uses `./bin/jakawi-test php artisan media:gc --dry-run`.

Normal orphan grace is **48 hours**, conservatively measured from the first GC observation of an unreferenced object (and only after the object is at least 48h old). Tiny private `media-gc/{sha256-key}.json` observation markers survive restarts without adding a DB media table. A referenced object clears its marker. Markers are internal lifecycle metadata, never public media and never included in managed object scans. Deletion rechecks every authoritative field immediately before removing the object. Successfully deleted objects have their marker removed. Temporary TTL is **24 hours** from object creation, matching receipt expiry; abandoned editor uploads and staged copies are collected automatically.

Schedule: once **daily at 03:20 America/La_Paz**, using the existing Laravel scheduler, with overlapping runs prevented. No additional external cron. GC only lists the explicit managed prefixes and only deletes recognized immutable/generated keys. `health/`, specifically `health/imgproxy-auth-test.txt`, backups, v2proof, unknown keys, unrelated buckets and other system namespaces are excluded. A reference-query or storage error fails closed and returns a failing command exit status. Runs are idempotent.

External URLs are not the canonical normal-image workflow. Publisher images use the same selector/service. Landing JSON V1 still accepts `media.mode` and `media.alt`; importing image source URLs or paths remains forbidden by its existing schema. Publisher save also rejects arbitrary hero paths while permitting an existing saved reference or authoritative product fallback for compatibility. Actual image selection belongs to the Publisher UI.

Live deployment uses Docker PHP 8.4 with GD/EXIF, private MinIO and signed imgproxy delivery. Production GC dry-run passed with zero deletions; the only production object remains `health/imgproxy-auth-test.txt` (41 bytes). No catalog records, users or QA media were created during release. The existing scheduler runs media GC daily at 03:20 America/La_Paz; normal orphan grace is 48h and temporary TTL is 24h.
